# MANILI

Интернет-магазин одежды MANILI: витрина-журнал, каталог, корзина, оформление
заказа, личный кабинет и админ-панель для владельца.

Сайт работает **сразу после `npm install && npm run dev`** — без настройки
backend: в демо-режиме данные живут в браузере. Appwrite подключается одной
переменной окружения, код при этом не меняется.

---

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
```

Демо-доступы (только в режиме `VITE_BACKEND=mock`):

| Что            | Как войти                                              |
|----------------|--------------------------------------------------------|
| Покупатель     | вход по телефону, код подтверждения `0000`             |
| Владелец       | кнопка «Войти как владелец (демо)» на странице `/login` |

Сборка и предпросмотр:

```bash
npm run build
npm run preview
```

Остальные команды:

| Команда | Что делает |
|---|---|
| `npm run typecheck` | Проверка типов |
| `npm run setup:appwrite` | Создаёт схему базы в Appwrite |
| `npm run seed:appwrite` | Заливает категории, коллекции, блоки главной |
| `npm run functions:build` | Готовит серверные функции к деплою |
| `npm run telegram:register` | Подключает Telegram-бота |

## Архитектура

Главное правило: **UI не знает, какой backend под ним**. Между ними лежит слой
репозиториев с описанными контрактами, поэтому смена Appwrite на что-то другое
не потребует переписывать интерфейс (ТЗ §4, §49).

```
src/
├── domain/          Типы предметной области и правила (деньги, остатки, статусы)
├── repositories/    Контракты доступа к данным
│   ├── contracts.ts   ← единственный интерфейс, который видит UI
│   ├── mock/          ← демо-реализация (localStorage)
│   └── appwrite/      ← боевая реализация
├── services/        Бизнес-логика поверх данных (события заказа)
├── api/             Конфигурация и HTTP-клиент серверных функций
├── store/           Состояние: корзина, избранное, авторизация
├── components/      UI-кит, медиа, motion, layout, витрина
├── pages/           Страницы (каждая — отдельный чанк сборки)
└── hooks/           Reveal, parallax, загрузка данных, SEO

functions/           Серверные функции Appwrite (Node)
├── shared/            общие модули: остатки, промокоды, провайдеры
├── create-order/      создание заказа: резерв, расчёт, платёж
├── payment-webhook/   единственное место, где заказ становится оплаченным
├── set-order-status/  админские операции и аналитика
├── check-promocode/   проверка промокода
└── quote-delivery/    расчёт доставки, ПВЗ, трекинг
```

### Что где считается

| Операция | Где | Почему |
|---|---|---|
| Цена и сумма заказа | сервер | браузеру нельзя доверять сумму (ТЗ §15) |
| Скидка по промокоду | сервер | иначе скидку подделают (ТЗ §13) |
| Остатки и резерв | сервер | защита от гонки за последним размером (ТЗ §35) |
| Статус «оплачен» | webhook | фронт не может объявить заказ оплаченным (ТЗ §37) |
| Права роли | сервер | роль читается из базы, а не из запроса (ТЗ §25) |

## Подключение сервисов

Пошаговая инструкция со скриншотами действий — **[docs/SETUP.md](docs/SETUP.md)**.
Там разобрано: логотип, GitHub Pages, домен, Appwrite, эквайринг, СДЭК,
Telegram, почта, SMS и юридическая часть.

Короткая версия по Appwrite — ниже.

## Подключение Appwrite

1. Создайте проект в [Appwrite Cloud](https://cloud.appwrite.io) или поднимите
   self-hosted.
2. Создайте API-ключ с правами на `databases` и `storage`.
3. Разверните схему базы:

   ```bash
   APPWRITE_ENDPOINT=https://cloud.appwrite.io/v1 \
   APPWRITE_PROJECT_ID=xxx \
   APPWRITE_API_KEY=xxx \
   npm run setup:appwrite
   ```

4. Наполните базу стартовым содержимым:

   ```bash
   APPWRITE_ENDPOINT=... APPWRITE_PROJECT_ID=... APPWRITE_API_KEY=... \
   npm run seed:appwrite
   ```

5. Соберите и разверните функции:

   ```bash
   npm run functions:build     # готовит build/functions/
   appwrite push functions     # или загрузите ZIP через консоль
   ```

   Переменные окружения функций — раздел SERVER-SIDE в `.env.example`.
6. В `.env` фронтенда укажите:

   ```
   VITE_BACKEND=appwrite
   VITE_APPWRITE_ENDPOINT=https://cloud.appwrite.io/v1
   VITE_APPWRITE_PROJECT_ID=xxx
   ```

7. В коллекции `profiles` поставьте своему документу `role = ADMIN`.

SDK Appwrite грузится отдельным чанком и в демо-сборку не попадает.

## Безопасность

Секреты **никогда** не попадают во фронтенд и в репозиторий:

- всё с префиксом `VITE_` видно в браузере — там только публичные значения;
- `APPWRITE_API_KEY`, ключи эквайера, `TELEGRAM_BOT_TOKEN`, ключи доставки и
  почты задаются только в переменных окружения серверных функций;
- `.env` в `.gitignore`, в репозитории лежит `.env.example` без значений.

Реализовано: идемпотентность заказа, проверка подписи webhook, сверка суммы
платежа с суммой заказа, откат резерва при сбое, журнал действий администратора,
проверка допустимых переходов статуса на сервере.

## Что нужно от владельца

Всё это — действия в чужих интерфейсах, из кода их не сделать.
Пошагово: **[docs/SETUP.md](docs/SETUP.md)**.

- **Файл логотипа** → `public/brand/manili-logo.svg`
- **Фотосъёмка** — загружается в админке, пока показываются плейсхолдеры
- **Аккаунт Appwrite** — база данных и хранилище файлов
- **Договор с эквайером** — ЮKassa или Т-Банк
- **Договор со СДЭК** — иначе работают фиксированные тарифы
- **Telegram-бот** — 10 минут через @BotFather
- **Реквизиты продавца** для оферты
- **Проверка юридических текстов** специалистом перед запуском

## Деплой

Публикация на GitHub Pages настроена в `.github/workflows/deploy.yml`:
push в `main` собирает проект и выкладывает `dist`.

Публичные переменные задаются в Settings → Secrets and variables → Actions →
**Variables** (не Secrets — это не секреты).

Домен пока не подключён — сайт живёт на адресе GitHub вида
`https://<логин>.github.io/<репозиторий>/`. Базовый путь сборка определяет
сама: есть `public/CNAME` — публикуем в корень домена, нет — в подпапку
репозитория. Как вернуть домен — `public/brand/DOMAIN.txt`.

Прямые ссылки вида `/product/hoodie-classic` работают благодаря `404.html`,
который создаётся при сборке.
