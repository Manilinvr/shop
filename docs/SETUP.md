# MANILI — пошаговая настройка

Всё, что нельзя сделать из кода: регистрации, договоры, ключи, кнопки в чужих
интерфейсах. Разделы независимы — магазин работает и без них, просто с
отключёнными возможностями.

**Порядок по важности.** Шаги 1–3 нужны, чтобы сайт открылся в интернете.
Шаги 4–6 — чтобы принимать деньги и отправлять заказы. Остальное — по мере
готовности.

## 1. Логотип и фотографии

### Логотип

1. Подготовьте файл логотипа в формате **SVG** (векторный, не картинка).
   Если есть только растр — подойдёт PNG с прозрачным фоном, шириной от 600 px.
2. Назовите его `manili-logo.svg` и положите в папку `public/brand/`.
3. Если есть кириллическая версия «Манили» — рядом как `manili-logo-ru.svg`.
4. Замените `public/favicon.svg` — это иконка вкладки браузера.

Сайт подхватит логотип сам, править код не нужно. Пока файла нет, в шапке
выводится нейтральная надпись MANILI без выдуманных знаков.

### Фотографии товаров

Загружаются прямо в админке: **Товары → выберите товар → Фотографии**.
Перетащите файлы или нажмите на область загрузки.

- Первый кадр — главный в каталоге, второй показывается при наведении
- Порядок меняется стрелками, лишнее удаляется корзиной
- До 8 кадров на товар, до 8 МБ каждый, JPG / PNG / WebP

**Важно:** до подключения Appwrite (шаг 4) фото хранится только в вашем
браузере — для примерки вида это нормально, но на другом устройстве его не
будет. После шага 4 файлы уходят в облако.

**Рекомендации по съёмке:** вертикальный кадр 3:4, ширина от 1600 px,
одинаковый фон и свет во всей серии.

## 2. GitHub Pages — сайт в интернете

**Уже настроено и работает.** Workflow сам переключает Pages в режим
«GitHub Actions» при запуске, руками лезть в настройки не нужно.

Каждый push в `main` публикует изменения автоматически. Запустить вручную:
**Actions** → *Deploy to GitHub Pages* → **Run workflow**.

### Если деплой падает: job `deploy` без шагов

Симптом: `build` зелёный, `deploy` красный, упал за пару секунд, логов нет
и в job не выделен runner. Это не ошибка сборки — окружение `github-pages`
отклонило запуск ещё до старта, потому что ветка не в списке разрешённых.

**Где чинится:** **Settings → Environments → github-pages** →
блок **Deployment branches and tags**.

Там либо выберите **All branches**, либо добавьте правило с именем `main`
(кнопка *Add deployment branch or tag rule*).

Важно: этот список **не обновляется сам** при смене основной ветки.
Если репозиторий начинал жизнь с другой веткой по умолчанию, в списке
останется её старое имя, и деплой с `main` будет молча отклоняться.

Заодно проверьте **Settings → General → Default branch** — там тоже
должна быть `main`.

### Если сайт открылся, но без стилей

Значит он лежит не в корне домена. Зайдите в **Settings → Secrets and variables
→ Actions → Variables** и добавьте:

```
VITE_BASE_PATH = /shop/
```

(вместо `shop` — имя вашего репозитория), затем перезапустите workflow.

адресу `*.github.io`.

## 4. Appwrite — база данных и хранилище

Без этого шага данные живут только в браузере: заказ, сделанный покупателем,
вы не увидите.

### 4.1. Проект

1. Зарегистрируйтесь на [cloud.appwrite.io](https://cloud.appwrite.io)
2. **Create project** → название `MANILI`
3. Выберите регион (ближе к покупателям — Frankfurt)
4. Скопируйте **Project ID** из *Settings → General*

### 4.2. API-ключ

1. *Overview → Integrations → API keys* → **Create API key**
2. Название: `manili-server`
3. Scopes — отметьте: `databases.read`, `databases.write`,
   `collections.read`, `collections.write`, `attributes.read`,
   `attributes.write`, `indexes.read`, `indexes.write`,
   `documents.read`, `documents.write`, `files.read`, `files.write`,
   `buckets.read`, `buckets.write`, `users.read`, `users.write`
4. Скопируйте ключ — **показывается один раз**

> Этот ключ даёт полный доступ к данным. Не отправляйте его в мессенджерах,
> не коммитьте в git, не вставляйте в поля с префиксом `VITE_`.

### 4.3. Схема базы

На своём компьютере, в папке проекта:

```bash
APPWRITE_ENDPOINT=https://fra.cloud.appwrite.io/v1 \
APPWRITE_PROJECT_ID=вставьте_project_id \
APPWRITE_API_KEY=вставьте_ключ \
npm run setup:appwrite
```

Endpoint возьмите из консоли Appwrite (*Settings → General → API Endpoint*).

Скрипт создаст 17 коллекций с атрибутами и индексами. Займёт 3–5 минут.
Повторный запуск безопасен: существующее пропускается.

### 4.4. Стартовое содержимое

```bash
APPWRITE_ENDPOINT=... APPWRITE_PROJECT_ID=... APPWRITE_API_KEY=... \
npm run seed:appwrite
```

Создаст категории, коллекции, блоки главной и промокоды-примеры.
Товары не создаются — их вы добавите сами.

Если хотите сначала посмотреть на заполненный магазин:

```bash
... npm run seed:appwrite -- --with-products
```

### 4.5. Функции

Соберите папки к деплою:

```bash
npm run functions:build
```

Дальше два пути.

**Через Appwrite CLI (быстрее):**

```bash
npm install -g appwrite-cli
appwrite login
```

В файле `appwrite.json` замените `PASTE_YOUR_PROJECT_ID` на свой Project ID, затем:

```bash
appwrite push functions
```

**Через консоль (без CLI):**

Для каждой из шести папок в `build/functions/`:

1. *Functions → Create function → Manual*
2. Name и Function ID — как имя папки (`create-order` и т. д.)
3. Runtime: **Node.js 22**
4. Entrypoint: `src/main.js`
5. Build command: `npm install`
6. Заархивируйте содержимое папки в ZIP и загрузите в *Deployments*

**Права запуска** (*Settings → Execute access* каждой функции):

| Функция | Доступ |
|---|---|
| create-order | Any |
| check-promocode | Any |
| quote-delivery | Any |
| payment-webhook | Any |
| telegram-webhook | Any |
| set-order-status | **Users** |

`payment-webhook` и `telegram-webhook` открыты для всех намеренно: их
вызывают внешние сервисы. Подлинность проверяется подписью внутри самой
функции, а не правами Appwrite.

### 4.6. Переменные функций

В каждой функции: *Settings → Environment variables*. Всем шести задайте:

```
APPWRITE_ENDPOINT      = https://fra.cloud.appwrite.io/v1
APPWRITE_PROJECT_ID    = ваш project id
APPWRITE_API_KEY       = ваш ключ
APPWRITE_DATABASE_ID   = manili
SITE_URL               = https://manili-event.ru
```

Остальные переменные — по мере подключения сервисов (шаги 5–9).

### 4.7. Переключение сайта на Appwrite

**GitHub → Settings → Secrets and variables → Actions → Variables:**

```
VITE_BACKEND              = appwrite
VITE_APPWRITE_ENDPOINT    = https://fra.cloud.appwrite.io/v1
VITE_APPWRITE_PROJECT_ID  = ваш project id
VITE_APPWRITE_DATABASE_ID = manili
VITE_APPWRITE_BUCKET_ID   = media
VITE_SITE_URL             = https://manili-event.ru
```

Это **Variables**, а не Secrets — здесь только публичные идентификаторы.

Перезапустите workflow во вкладке Actions.

### 4.8. Разрешить сайту обращаться к Appwrite

*Settings → Platforms → Add platform → Web app*

- Name: `MANILI`
- Hostname: `manili-event.ru`

Добавьте вторую платформу с hostname `*.github.io`, если пользуетесь и этим
адресом. Без этого шага браузер заблокирует запросы.

### 4.9. Сделать себя администратором

1. Откройте сайт → **Войти** → зарегистрируйтесь
2. В Appwrite: *Databases → manili → profiles* → найдите свой документ
3. Поле `role` → поменяйте `CUSTOMER` на `ADMIN` → **Update**
4. Обновите сайт — появится раздел **Админ-панель**

## 5. Приём оплаты

Выберите одного провайдера.

|  | ЮKassa | Т-Банк |
|---|---|---|
| Комиссия | от 2,8% | от 2,3% |
| Подключение | 1–3 дня | 1–2 дня, быстрее со счётом в банке |
| Проверка webhook | обратный запрос к API | подпись в уведомлении |
| Самозанятым | да | да |

Оба адаптера уже написаны — разница только в том, какие переменные задать.

### 5.1. ЮKassa

1. [yookassa.ru](https://yookassa.ru) → **Подключить**
2. Заполните данные бизнеса (ИП / ООО / самозанятый), дождитесь проверки
3. *Настройки → Магазин* → скопируйте **shopId**
4. *Настройки → API ключи* → **Выпустить секретный ключ**
5. *Настройки → HTTP-уведомления*:
   - URL: адрес функции `payment-webhook` из консоли Appwrite
     (*Functions → payment-webhook → Domains*, вид
     `https://<id>.appwrite.global/`)
   - События: `payment.succeeded`, `payment.canceled`

Переменные для **всех** функций:

```
PAYMENT_PROVIDER = yookassa
PAYMENT_SHOP_ID  = ваш shopId
PAYMENT_SECRET   = ваш секретный ключ
```

Если подключена онлайн-касса, дополнительно:

```
PAYMENT_RECEIPTS = 1
PAYMENT_VAT_CODE = 1
```

`VAT_CODE`: 1 — без НДС, 2 — 0%, 3 — 10%, 4 — 20%.

### 5.2. Т-Банк

1. [tbank.ru/kassa](https://www.tbank.ru/kassa/) → **Подключить**
2. После проверки: *Магазины → ваш магазин → Терминалы*
3. Скопируйте **Terminal Key** и **Пароль**
4. *Настройки терминала → Уведомления → Notification URL* — адрес функции
   `payment-webhook`

```
PAYMENT_PROVIDER = tbank
PAYMENT_SHOP_ID  = ваш Terminal Key
PAYMENT_SECRET   = ваш пароль
```

### 5.3. Проверка

1. Включите тестовый терминал у провайдера
2. Оформите заказ на сайте
3. Оплатите тестовой картой (номера есть в документации провайдера)
4. Заказ в админке должен перейти в **Оплачен**, остаток — уменьшиться

Если статус не поменялся: *Functions → payment-webhook → Executions* —
там видно, дошло ли уведомление и что ответила функция.

> Пока `PAYMENT_PROVIDER` не задан, заказы создаются в статусе
> «Ожидает оплаты». Магазин работает, вы выставляете счёт вручную.

## 6. Доставка СДЭК

1. [cdek.ru](https://www.cdek.ru/ru/integration) → договор с интеграцией
2. В личном кабинете: *Настройки → Интеграция → API* → **Account** и **Secure password**
3. Узнайте код города отправления: *Интеграция → Справочники → Города*

Переменные:

```
DELIVERY_PROVIDER       = cdek
DELIVERY_ACCOUNT        = ваш Account
DELIVERY_API_KEY        = ваш Secure password
DELIVERY_FROM_CITY_CODE = код вашего города (Москва = 44)
```

**Без СДЭК** магазин считает доставку по вашим тарифам:

```
DELIVERY_PRICE_PVZ           = 35000   (350 ₽, значения в копейках)
DELIVERY_PRICE_COURIER       = 45000
DELIVERY_PRICE_POST          = 30000
DELIVERY_SELF_PICKUP_ADDRESS = Москва, ул. Примерная, 1
FREE_DELIVERY_THRESHOLD      = 1000000  (бесплатно от 10 000 ₽)
```

Суммы в копейках: 350 ₽ = 35000.

## 7. Telegram — уведомления о заказах

### 7.1. Бот

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`
2. Имя: `MANILI заказы`, username: например `manili_orders_bot`
3. Скопируйте токен вида `1234567890:AAH...`
4. Откройте своего бота и нажмите **Start**

### 7.2. Узнать chat_id и привязать webhook

Придумайте секретную строку (любые 20+ символов) и выполните:

```bash
TELEGRAM_BOT_TOKEN=ваш_токен \
node scripts/register-telegram-webhook.mjs
```

Скрипт покажет ваш `chat_id`. Затем, подставив адрес функции
`telegram-webhook` из консоли Appwrite:

```bash
TELEGRAM_BOT_TOKEN=ваш_токен \
TELEGRAM_WEBHOOK_URL=https://<id>.appwrite.global/ \
TELEGRAM_WEBHOOK_SECRET=ваша_секретная_строка \
node scripts/register-telegram-webhook.mjs
```

### 7.3. Переменные

```
TELEGRAM_BOT_TOKEN      = токен от BotFather
TELEGRAM_OWNER_CHAT_ID  = chat_id из скрипта
TELEGRAM_WEBHOOK_SECRET = та же секретная строка
```

Теперь при каждом заказе придёт сообщение с составом, суммой и кнопками
**В работу / Готов к отправке / Заказ выполнен** — статус меняется прямо
из чата, заходить в админку не нужно.

Действия принимаются только из вашего чата: чужие нажатия отклоняются.

## 8. Email-уведомления

Подойдёт любой сервис транзакционной почты. Пример — Unisender Go
(российский, есть бесплатный тариф).

1. [go.unisender.ru](https://go.unisender.ru) → регистрация
2. Подтвердите домен отправителя (записи DKIM/SPF в DNS — сервис подскажет)
3. *Настройки → API* → скопируйте ключ

```
EMAIL_API_KEY   = ваш ключ
EMAIL_FROM      = orders@manili-event.ru
EMAIL_FROM_NAME = MANILI
EMAIL_OWNER     = ваша почта для копий заказов
```

Для другого сервиса (SendGrid, Resend, Mailgun) добавьте:

```
EMAIL_API_URL = адрес их API отправки
```

Формат запроса совместим с большинством; если нет — правится один `fetch`
в `functions/shared/notifications/email.js`.

Без этих переменных письма просто не отправляются, заказы работают.

## 9. SMS для входа по телефону

Appwrite отправляет SMS сам, нужен только провайдер.

*Messaging → Providers → Add provider → SMS* → выберите доступного
(Twilio, Vonage, MSG91, Textmagic) и введите его ключи.

Для России обычно нужен российский провайдер (SMS.RU, SMSC) — в этом случае
Appwrite Cloud может не подойти, и SMS подключается через отдельную функцию.
Скажите, если понадобится — допишу адаптер.

Пока SMS не подключён, работает вход по email с паролем.

## 10. Юридическая часть

Тексты в `/legal/privacy`, `/legal/terms`, `/legal/offer` — рабочие
заготовки. **Перед запуском их обязан проверить юрист.**

Заполните реквизиты продавца в оферте:

- Полное наименование ИП / ООО / самозанятого
- ИНН, ОГРН(ИП)
- Юридический адрес
- Банковские реквизиты
- Контакты для претензий

Редактируется в `src/pages/LegalPage.tsx` — или скажите, я внесу.

Дополнительно может понадобиться:

- Уведомление в Роскомнадзор об обработке персональных данных
- Подключение онлайн-кассы по 54-ФЗ (или агентская схема у эквайера)

Пройдите сами как покупатель:

- [ ] Товар открывается, размеры и остатки верные
- [ ] Добавление в корзину, изменение количества, удаление

- [ ] Оформление проходит все четыре шага
- [ ] Оплата тестовой картой завершается успешно
- [ ] Заказ появился в админке со статусом **Оплачен**
- [ ] В Telegram пришло уведомление, кнопки меняют статус
- [ ] Остаток уменьшился ровно на количество в заказе
- [ ] Покупателю пришло письмо (если почта подключена)
- [ ] Заказ виден в личном кабинете и по номеру+телефону
- [ ] Отмена заказа возвращает остаток на склад
- [ ] Всё то же самое с телефона

## Если что-то не работает

| Симптом | Где смотреть |
|---|---|
| Сайт не открылся после деплоя | GitHub → Actions → лог workflow |
| Пустой каталог | Appwrite → Databases → products: есть ли записи со `status = PUBLISHED` |
| «Сервис временно недоступен» | Functions → нужная функция → Executions → лог |
| Оплата не подтверждается | Functions → payment-webhook → Executions |
| Браузер блокирует запросы | Appwrite → Settings → Platforms: добавлен ли ваш домен |
| Нет доступа к админке | profiles → ваш документ → `role` = `ADMIN` |
| Telegram молчит | `getWebhookInfo` покажет ошибку: запустите скрипт из шага 7.2 |

Логи функций Appwrite хранят только техническую информацию. Пароли,
данные карт и секретные ключи туда не пишутся.
