# MANILI — архитектурные решения

Короткие ответы на вопрос «почему так сделано».

## Backend можно заменить

UI импортирует `backend` из `src/repositories` и работает только с
интерфейсами из `contracts.ts`. Реализаций две: `mock` (данные в браузере)
и `appwrite`. Выбор — переменная `VITE_BACKEND`; при публикации на
GitHub Pages её выставляет workflow по переменной репозитория `SITE_MODE`
(`live` — Appwrite, иначе демо).

Появится третий backend — добавится папка рядом и ветка в фабрике.
Ни одна страница при этом не меняется (ТЗ §4, §49).

## Критичное считает сервер

Фронтенд не может повлиять на сумму заказа, скидку, остатки и статус оплаты.
Всё это — серверные функции в `functions/`. Браузер присылает только
намерение («хочу вот эти варианты в таком количестве»), сервер пересчитывает
состав по базе.

## Защита от гонки за последним размером

`functions/shared/stock.js` использует оптимистическую блокировку: читаем
вариант с полем `version`, пишем `version + 1`, перечитываем и убеждаемся,
что запись наша. Иначе — повтор с задержкой. Резерв на заказ ставится
«всё или ничего»: при неудаче по одной позиции уже поставленные откатываются.

Ограничение честно зафиксировано в коде: строгую гарантию даёт только БД
с транзакциями. Логика собрана в одном модуле, поэтому переезд на
self-hosted PostgreSQL не заденет вызывающий код.

## Идемпотентность заказа

Checkout генерирует `idempotencyKey` один раз на сессию оформления.
В коллекции `orders` на это поле стоит уникальный индекс: два одновременных
запроса физически не создадут два заказа. Повтор возвращает уже созданный.

## Оплата подтверждается только webhook

`create-order` всегда создаёт заказ в статусе «Ожидает оплаты». Перевести его
в «Оплачен» может только `payment-webhook` — после проверки подписи (Т-Банк)
или обратного запроса к API (ЮKassa) и сверки суммы с заказом.

## Уведомления не ломают заказ

`functions/shared/notifications/index.js` — таблица «событие → каналы».
Каждый канал выполняется независимо, ошибки пишутся в `notification_logs`.
Упавший Telegram не отменяет заказ. Новый канал — новая строка в таблице.

## Анимации без библиотек

Вместо анимационного пакета — один общий `IntersectionObserver` на все
reveal-элементы и один `requestAnimationFrame`-цикл на весь параллакс.
Анимируются только `transform` и `opacity`, поэтому кадры считает композитор.

Отдельный момент: «шторка» image-reveal сделана слоем `::after`, а не
`clip-path` на самом элементе. Элемент, обрезанный в ноль, считается
невидимым для `IntersectionObserver`, и анимация не запускалась бы никогда.

## Медиа-плейсхолдеры

Съёмки бренда пока нет, поэтому `Media` рисует процедурный SVG с силуэтом
вещи в фирменной палитре. Ссылки вида `placeholder:hoodie/1` заменяются на
реальные URL в данных — компоненты не трогаем.

## Скругления как система

Все радиусы — токены в `tokens.css`, кнопки только `--r-pill`. Это не
декоративное решение, а требование дизайн-системы: острых углов и
прямоугольных кнопок в интерфейсе нет.
