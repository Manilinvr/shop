# MANILI — серверные функции

Функции Appwrite. Всё, что нельзя доверить браузеру, живёт здесь.

## Список

| Функция | Что делает | Кто вызывает |
|---|---|---|
| `create-order` | Резервирует остатки, пересчитывает сумму, создаёт заказ и платёж | Checkout |
| `payment-webhook` | Подтверждает оплату, списывает остатки, шлёт уведомления | Платёжный провайдер |
| `set-order-status` | Смена статуса, трек-номер, остатки, роли, аналитика | Админка |
| `check-promocode` | Проверяет промокод и считает скидку | Корзина и checkout |
| `quote-delivery` | Тарифы, ПВЗ, подсказка городов, трекинг | Checkout |

## Установка

Для каждой функции в Appwrite:

- **Runtime:** Node.js 18+
- **Entrypoint:** `src/main.js`
- **Build command:** `npm install`
- **Execute access:** `users` для всех, кроме `payment-webhook` (там `any`,
  но подлинность проверяется подписью провайдера)

Папку `shared/` нужно класть рядом с `src/` внутрь каждой функции при
деплое — она подключается относительными путями `../../shared/...`.

## Переменные окружения

Смотрите раздел SERVER-SIDE в `.env.example`. Обязательный минимум:

```
APPWRITE_ENDPOINT
APPWRITE_PROJECT_ID
APPWRITE_API_KEY
APPWRITE_DATABASE_ID
SITE_URL
```

Без `PAYMENT_PROVIDER` заказ создаётся в статусе «Ожидает оплаты», и владелец
выставляет счёт вручную — магазин остаётся рабочим.

## Webhook платёжной системы

URL вебхука указывается в личном кабинете эквайера и ведёт на функцию
`payment-webhook`. Проверка подлинности:

- **ЮKassa** уведомления не подписывает → делаем обратный запрос к её API
  и верим только ответу провайдера;
- **Т-Банк** подписывает поле `Token` → сверяем подпись.

В обоих случаях сумма платежа сверяется с суммой заказа из базы. При
расхождении заказ уходит в статус «Проблема», и владелец разбирается вручную.
